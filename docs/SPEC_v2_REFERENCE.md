# v2.0 参照仕様（要約）

この文書は Library に保存されている「思考の地図 v2.0.pdf」から、v3 設計で失ってはいけない要素を抜き出した参照版。

## 1. v2 の基本姿勢

本アプリは次を目的にしない。

- IQ測定
- 医学的・心理学的診断
- 発達障害等の判定
- 固定的な「○○型」分類
- 学習スタイル分類
- 一回のテストから恒久的な能力判定
- 高得点 = 頭が良い、低得点 = 能力が低いという評価

## 2. 3層モデル

### Performance
実際に何ができたか。

例:
- 正確に覚えられた
- 位置関係を再構築できた
- 原因を推測できた
- 規則を発見できた
- 他者の知識状態を区別できた

### Strategy
どう解いたか。

同じ正答でも、
- 映像化
- 言語化
- 空間関係だけ保持
- 抽象関係として保持
など複数の解法があり得る。

### Experience
本人にはどう感じられたか。

例:
- 映像が鮮明
- ぼんやり配置だけ
- 言葉を反復
- 自分に説明
- 言葉も絵もなく意味だけ分かる
- 分かるが説明しにくい

Experience は能力点へ直接変換せず、Performance と照合する。

単語だけ差し替えたテンプレート反復は禁止。

## 6. 練習効果対策

- 同一文章を文字と音声で短時間に再提示しない
- 同型・同負荷の別問題で比較する
- 提示順を固定しない
- 本番前の練習問題は得点に入れない
- 同じ具体問題を再利用しない
- 同じ構造を過剰反復しない
- 問題構造 Fingerprint を保存する
- 同じ能力を別形式でも測る

## 7. 採点と表示

- 一つの回答を多数の能力スコアへ無制限に流用しない
- 原則として1能力につき最低3観察、かつ最低2種類の課題形式
- 条件未達では数値を強調せず「観察不足」
- データ量に応じて「観察不足 / 暫定 / ある程度安定 / 比較的安定」
- 最初に数字を大量表示せず、自然文で今回の特徴を示す

## 9. v3への原則

v3 はこの測定モデルを捨てない。

v2 の A〜F は「何を観察したか」を記述する測定軸。
v3 の11理論領域は「どの認知過程・研究枠組みから課題を設計したか」を表す Process Lens。

両者を二層で持つ。
