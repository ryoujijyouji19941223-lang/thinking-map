# テスト設計原則

## 1. 「教えてから測る」を避ける

専門家レッスンで方法を教えた直後の成績は、元々の思考傾向ではなく「教えた方法を使えるか」を含む。

そのため原則は:

1. 初見
2. レッスン
3. 練習
4. 転移
5. 遅延

の順にする。

## 2. 表面構造を繰り返さない

同じ人物配置、同じ時系列、同じ質問順を繰り返すと、問題の意味ではなく出題パターンを学習できてしまう。

変えるもの:
- 題材
- 時系列
- 登場人物数
- 情報量
- 画像/文章/音声
- 質問位置
- 因果の向き
- 正解に必要な手掛かり

保持するもの:
- 測りたい認知操作

## 3. 1問で能力を決めない

同じ能力を少なくとも複数形式で測る。

例: 欠落検知
- 画像
- 文章
- 会話
- 図表

## 4. 事実・推測・判断を分ける

観察課題では回答欄自体を分離する。

- 見えた事実
- そこから考えたこと
- まだ分からないこと
- 判断

これにより、正答だけでなく「どこで推論へ移ったか」を見られる。

## 5. 自信度を標準化する

回答後に 0–100% の自信度を記録する。

「自信が高いほど良い」とは扱わない。正答との対応を見る。

## 6. 情報更新課題

最初の回答と自信を固定した後、新情報を追加する。

記録:
- 結論を変えたか
- どれだけ確率を変えたか
- 理由を変更したか
- 変更しなかった理由

## 7. 条件比較

同じ認知操作について、条件を変えて比較する。

候補:
- 文字 / 音声 / 画像
- 時間制限あり / なし
- メモ可 / 不可
- ジェスチャー自由 / 手を使わない
- 図を描ける / 描けない
- 個別提示 / 比較提示
- 即時 / 遅延

## 8. 問題生成

完全ランダム文章ではなく、問題テンプレートに「検証可能な正解条件」を持たせる。

生成後に自動検査:
- 情報不足ではないか
- 複数正解が意図せず存在しないか
- 特定語だけで解けないか
- 過去問題と表面構造が似すぎていないか
- 学習済みルールをそのまま要求していないか
